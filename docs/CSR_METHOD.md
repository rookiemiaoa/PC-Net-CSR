# CSR：把弱监督时刻检索的主战场从「边界」移到「中心」

> 方法说明。数字全部来自 `RESULTS.md`，脚本见 `csr/`。

---

## 1. 问题：为什么"扩框"这条路走不通

PC-Net 论文自述的痛点是长动作的**起止点连接失败**：弱监督框在长动作上盖不住两端。
最直接的补救是推理期把框往两边扩（本文记为 **RBR**，Relevance Boundary Refinement）。
实测（Charades-CG Test-Trivial，官方权重，K_REP=3）RBR 确实是"有效"的：

| | ΔR1@0.5 | ΔR1@0.7 | ΔmIoU |
|---|---:|---:|---:|
| RBR k=0.15（全量） | **−0.97** | +1.09 | +1.08 |
| RBR k=0.15 短动作桶（gt ≤ 0.35） | **−2.98** | −2.21 | −0.17 |
| RBR k=0.15 长动作桶（gt > 0.35） | +4.77 | **+10.49** | +4.66 |

长动作大涨、短动作大跌，headline 指标（R1@0.5）**转负**。这不是调参问题：

> 扩框对单样本的收益符号是 **sign(g − w)**（g = gt 时长，w = 基线框宽）。
> Charades-CG 的基线框中位宽 0.341，而 gt 时长中位约 0.25–0.31 ⇒ **多数样本 g < w**
> ⇒ 扩框对多数样本天然有害。损伤与收益**同比例**变化，任何纯全局的阈值/阻尼都只能
> 同比例缩小二者，**无法把"短不降"和"长显著增"分开**。

这就是 RBR 路线的**结构性方向偏置**：它不是参数没调好，而是算子的符号本身就带偏。
（把这些尝试逐个证伪的过程记录在 `csr/diagnostics/` 下，共 6 个脚本、300+ 变体。）

## 2. 观察：IoU 对「中心」是偶函数

固定框宽不变，只移动中心 δ：

```
IoU(δ) = IoU(−δ)，且在 δ = 0 处取极大
```

⇒ **中心修正没有子群方向偏置**：一个样本要么受益要么不受益，不存在"按 gt 长短系统性站边"。
把中心换成 gt（保持框宽）的 **ORACLE_c** 在 Charades-CG 上实测：

| | mIoU |
|---|---:|
| 基线 | 0.4720 |
| ORACLE_c（只换 gt 中心，框宽不变） | **0.7040** |
| | 短桶 +20.7pt / 长桶 +30.4pt，**两个子群同时受益** |

反过来，同样用 gt 去 oracle 地修**边界**（ORACLE_gate 上界）只能拿到 +1.29 / +12.48，
且短桶为正的前提是"不对短样本动手"。⇒ **真正的瓶颈是中心，不是边界。**

---

## 3. 方法：CSR（Center-Shift Refinement）

**零训练、零可学参数、推理期、不使用任何 gt。** 五步：

1. **逐点提案 → 相关性曲线**：把 `proposal_generator` 临时替换成 L = 50 个等间距的固定
   逐点提案（PC-Net 的重建分辨率 200/4 = 50），前向一次得到逐帧相关性
   `r(t) = −nll(t)`；**先逐样本 z-score 再平滑**（顺序不可颠倒，先平滑会把 z-score 的尺度带歪）。
2. **中心估计**：在窗口 `[c_b − β, c_b + β]`（β = 0.20）内，对 `relu(Z)` 取加权质心，得 `c₁`。
3. **dead-zone**：若 `|c₁ − c_b| < ρ·w_b`（ρ = 0.10）则**不平移**。
   这一步专门保护"中心本来就准"的样本——它们是短样本伤害的唯一来源。
4. **阻尼**：`c₂ = c_b + α·(c₁ − c_b)`（α = 1.00）。
5. **自洽门控**（弱监督可算的接受准则）：仅当平移后**框内 Z 均值**的提升 ≥ dmin（0.01）
   才接受，否则退回原中心。
6. **宽度保持不变**——这是与 RBR 的本质区别：短样本不会因宽度变化而跨过 0.5 阈值。

```
基线框  [bL ─────────── bH]
              ↓ 只动中心，宽度原样
CSR  框      [bL' ────────── bH']
```

返回 `boxes_top1`（供 R@1）与 `boxes_pool5`（CSR 框顶替原 top-1 + 原 rank2..5，供 R@5）。

### 默认超参

| 超参 | 值 | 含义 |
|---|---:|---|
| `smooth` | 7 | 相关性曲线平滑窗口 |
| `beta` | 0.20 | 中心估计搜索窗口半径（归一化时长单位） |
| `rho` | 0.10 | dead-zone 阈值 = ρ × 框宽 |
| `alpha` | 1.00 | 位移阻尼 |
| `dmin` | 0.01 | 自洽门控阈值（`None` 关闭） |
| `num_point` | 50 | 逐点提案数（= `max_num_frames // 4`） |

**超参来源（无测试集泄漏）**：仅在 **`data/charades/train.json`（开发集）**上按"短样本优先"准则
从 900 组网格中挑选，再**原样**用于三个测试切分。train 达标 217/900、test 达标 97/900、
交集 81 组（37.3%）⇒ 解区域跨切分稳定。推理期不含 gt。

## 4. 有效性的判据：两轴有效图

推理期精修只在特定**几何**下有效，判据是「基线框宽 / gt 时长」之比：

| 比值 | 几何 | 哪个轴有效 | 子群偏置 |
|---|---|---|---|
| **< 1** | 框比动作短 | 扩框（RBR） | **有**：符号 = sign(g−w)，伤多数子群 |
| **≈ 1.3 – 1.9** | 框与动作相当 | **移中心（CSR）** | **无**：IoU 对 δ 是偶函数 |
| **> 3** | 框远宽于动作 | 两轴都无着力点 | — |

三个实测落点：Charades-CG / PC-Net = **1.35**（CSR 全正）；Charades-CG / CNM = **1.73**（CSR 全正）；
ActivityNet-CG / PC-Net = **3.60**（CSR 失效）。

> 这条判据同时解释了本文的**负结果**：ActivityNet-CG 上基线框宽中位 0.9908、gt 时长中位 0.2750
> （≈3.6×），此时 `IoU ≈ gt/框宽` 由**宽度**决定，而 CSR 是宽度保持型算子 ⇒ 结构性无从下手。
> 10 组单变量扫描 **10/10 全负**，且 ORACLE 上界极低（+0.03/+0.34/+0.42）⇒ 不是调参问题。

## 5. 为什么它是"机理"而不是"后处理小技巧"

**跨骨干零调参迁移**：把 CSR（超参一字不改）搬到外部弱监督基线 **CNM**（AAAI-2022）
的冻结权重上，三个切分 × 三个指标**九格全正，且每格增幅都大于 PC-Net**：

| 切分 | ΔR1@0.5 | ΔR1@0.7 | ΔmIoU |
|---|---:|---:|---:|
| CNM Test-Trivial | **+5.19** | +2.23 | +3.00 |
| CNM Novel-Comp | +3.41 | +1.62 | +2.17 |
| CNM Novel-Word | +4.56 | +3.55 | +2.84 |

且 **CNM 的短动作桶三切分三指标全部为正**（PC-Net 上只能做到"不显著下降"）。
同权重同曲线下 RBR 在 Test-Trivial 的 ΔR1@0.5 只有 **+0.01**。

能零调参迁移的前提：CNM 的 `max_num_frames` 同样是 200 ⇒ 逐点网格 L = 50 与 PC-Net 完全相同。
曲线从 CNM 自己的掩码重建阶段读出（`decoding=2` + 尖峰高斯掩码 `WPT=0.1`），不改权重、不读 gt。

**诚实例外**：自洽门控在 PC-Net 上是承重的（关掉后短动作 @0.7 从 +0.22 掉到 −3.20），
在 CNM 上则是**中性略有害**（+3.00 vs 关掉门控的 +3.45）。适用条件正比于
"本来正确的中心"占比（PC-Net 短桶 46.6%）。WPT 四点扫描（0.1→0.3）显示 CSR 恒正、RBR 恒劣
⇒ 结论不依赖这个旋钮。

## 6. 被证伪的路线（供审稿人查证）

以下路线均已实跑并证伪，脚本与结论留在 `csr/diagnostics/`：

| 路线 | 关键数字 | 结论 |
|---|---|---|
| RBR 边界扩框族（k 扫描） | 短 @0.5 最好 −0.775 | 方向偏置，无法分离子群 |
| 纯全局阻尼（CAP/MIN/SNAP/MIX/GATE） | 短伤与长益**同比例**缩放 | 结构性无效 |
| 峰值相对阈值（PRK/PRR） | 短 −3.27 / 长 +11.77 | 仍无法分离 |
| Edge-Grow 边界外推 | 短伤 −2.98 → −0.45，但长 @0.7 只剩 +4.19 | 只是"更少动手"，不是"更会分辨" |
| Edge-Grow 判定当门控 | 最佳短 −0.99（仍为负） | 布尔判据不够 |
| 对称生长 + 对比度门控 | 最佳短 −0.80 | 同上 |
| 逐侧信号筛选（AUC 诊断） | "边框外是否有平台" AUC ≈ **0.52** | **信号本身不可分**，这才是 300+ 变体全灭的原因 |
| 对称生长上界（ORACLE_sym） | Charades +0.46/+0.83，TACoS = 0.00 | 对称生长结构性无效（`min(ΔL,ΔR)` 掐掉增益） |
| ANET 上的 10 组标量扫描 | 10/10 全负 | 几何失配，非调参问题 |

最后一条尤为关键：`ORACLE_side`（逐侧 oracle）能拿 +3.71 / +17.66，
但**无 gt 判据不可分** ⇒ 这条路的收益无法在弱监督下兑现，故转向中心轴。
